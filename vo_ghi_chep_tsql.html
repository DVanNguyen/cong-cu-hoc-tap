Slide #3

Transact-SQL (T-SQL) & Khối lệnh BEGIN...END

📑 Khung sườn Slide gốc:

  • T-SQL tổ chức theo từng khối lệnh, một khối lệnh có thể lồng bên trong một khối lệnh khác.
  • Một khối lệnh bắt đầu bởi BEGIN và kết thúc bởi END.
  • Các câu lệnh ngăn cách nhau bởi dấu chấm phẩy (;).
BEGIN
    -- Khai báo biến
    -- Các câu lệnh T-SQL
END;

Lời thầy giảng giải thích chi tiết:

  • Tại sao phải dùng BEGIN...END? Thầy giải thích nó tương tự như cặp dấu ngoặc nhọn { } trong C++, C# hay Java, giúp SQL Server xác định ranh giới một nhóm lệnh được thực thi cùng nhau khi thỏa điều kiện logic.
  • Khối lệnh lồng nhau: Bên trong một khối lệnh cha có thể chứa nhiều khối lệnh con khác.
  • Dấu chấm phẩy (;): Thầy dặn sinh viên nên tập thói quen chấm phẩy ở cuối mỗi lệnh để viết code chuẩn ANSI.
Slide #4

Khai báo biến (DECLARE)

📑 Khung sườn Slide gốc:

Cú pháp: DECLARE @Tên_Biến Kiểu_Dữ_Liệu

DECLARE @Tuoi int
DECLARE @MSSV varchar(5)
DECLARE @numCount int

Quy tắc: Tên biến bắt đầu bằng ký tự @. Kiểu dữ liệu lấy kiểu dữ liệu hệ thống, trừ kiểu text, ntext, image.

Lời thầy giảng giải thích chi tiết:

  • Lý do phải có biến: Thầy giảng rằng biến là công cụ để truyền tham số và lưu trữ dữ liệu trung gian khi sau này học viết Stored Procedure, Function và Trigger.
  • Bắt buộc có tiền tố @: Nếu không có dấu @, SQL Server sẽ hiểu nhầm đó là tên cột trong bảng và quăng lỗi.
  • Lưu ý về text/ntext/image: Thầy giải thích đây là các kiểu dữ liệu cũ đã lỗi thời (deprecated), nên dùng nvarchar(max) hoặc varbinary(max) thay thế.
Slide #5, 6, 7

3 Cách Gán Giá Trị Cho Biến: SET, SELECT & Truy Vấn Bảng

📑 Khung sườn Slide gốc:

-- Cách 1: Dùng lệnh SET
SET @HoTen = N'Nguyễn Hằng Nga'

-- Cách 2: Dùng lệnh SELECT
SELECT @HoTen = N'Nguyễn Hằng Nga'

-- Cách 3: Lấy từ kết quả câu truy vấn bảng
DECLARE @MaxSalary decimal(18,2)
SELECT @MaxSalary = MAX(Luong) FROM NhanVien

Lời thầy giảng giải thích chi tiết:

  • Chữ N viết hoa: Khi gán tiếng Việt có dấu cho biến nvarchar, bắt buộc phải có tiền tố N trước chuỗi. Nếu không có chữ N, chuỗi sẽ biến thành dấu chấm hỏi (????).
  • SET vs SELECT: Lệnh SET mỗi dòng chỉ gán được 1 biến đơn lẻ. Lệnh SELECT có thể gán cùng lúc cho hàng loạt biến trên cùng một dòng lệnh (SELECT @a = 1, @b = 2).
  • Cảnh báo nguy hiểm khi lấy từ bảng (Cách 3): Câu lệnh truy vấn chỉ an toàn khi trả về duy nhất 1 dòng. Nếu bảng trả về 100 dòng, biến sẽ nhận giá trị của dòng cuối cùng mà không hề báo lỗi, dẫn đến sai sót dữ liệu âm thầm!
Slide #9

Biến Kiểu Bảng (Table Variable)

📑 Khung sườn Slide gốc:

DECLARE @TableVariable table(
    course_name varchar(200),
    course_price int
);
INSERT INTO @TableVariable (course_name, course_price)
SELECT name, price FROM Training_Course WHERE id in (1,2);
SELECT course_name, course_price FROM @TableVariable;

Lời thầy giảng giải thích chi tiết:

Thầy giải thích biến bảng thực chất là một bảng dữ liệu tạm được lưu trữ chủ yếu trong bộ nhớ RAM. Nó hoạt động như bảng thật (có cột, kiểu dữ liệu, INSERT, SELECT). Thầy khuyên dùng biến bảng khi tập dữ liệu nhỏ (dưới vài trăm dòng) để tính toán trung gian. Khi kết thúc phiên làm việc, bộ nhớ RAM tự động giải phóng, không gây rác CSDL.

Slide #16, 17

Vòng Lặp WHILE & Điều Khiển BREAK, CONTINUE

📑 Khung sườn Slide gốc: Tính tổng S = 1 + 2 + ... + N

DECLARE @i INT, @N INT, @S INT
SELECT @i = 1, @S = 0
WHILE (@i <= @N)
BEGIN
    SELECT @S = @S + @i
    SELECT @i = @i + 1
END
PRINT @S

Lời thầy giảng giải thích chi tiết:

  • Khởi tạo @S = 0 và @i = 1: Thầy nhấn mạnh nếu không gán giá trị khởi tạo, biến mang giá trị NULL, mọi phép cộng với NULL đều ra kết quả NULL (sai hoàn toàn bài toán).
  • Tránh vòng lặp vô tận: Dòng SELECT @i = @i + 1 là điều kiện tiến tới điểm dừng. Nếu quên, chương trình chạy vô tận làm đứng CPU của server.
  • BREAK vs CONTINUE: BREAK thoát hẳn khỏi vòng lặp ngay lập tức; CONTINUE bỏ qua các lệnh phía dưới và chuyển sang lần lặp kế tiếp.
Slide #18

Các Biến Toàn Cục Quan Trọng: @@ERROR, @@IDENTITY, @@ROWCOUNT

📑 Khung sườn Slide gốc:

  • @@ERROR = 0: Lệnh trước đó thành công; @@ERROR <> 0: Có lỗi xảy ra.
  • @@IDENTITY: Giá trị tự tăng gần nhất vừa chèn vào bảng.
  • @@ROWCOUNT: Số lượng dòng bị tác động bởi lệnh SQL vừa rồi.

Lời thầy giảng giải thích chi tiết:

  • Phân biệt @ và @@: Một dấu @ là biến cục bộ do người dùng tạo; hai dấu @@ là biến toàn cục của hệ thống SQL Server quản lý, ta chỉ có quyền đọc giá trị.
  • Lưu ý về @@ERROR: Biến này sẽ bị xóa về 0 ngay lập tức sau lệnh kế tiếp nếu lệnh đó thành công. Do đó cần gán ngay vào một biến tạm (SET @Loi = @@ERROR) trước khi làm việc khác.
  • Ứng dụng @@IDENTITY: Dùng khi thêm một hóa đơn mới, ta lấy ngay mã hóa đơn tự tăng để thêm các mặt hàng chi tiết vào bảng ChiTietHoaDon.
Slide #20, 21

Xử Lý Ngoại Lệ & Bẫy Lỗi (BEGIN TRY...BEGIN CATCH)

📑 Khung sườn Slide gốc:

BEGIN TRY
    -- Lệnh xử lý nghiệp vụ
END TRY
BEGIN CATCH
    -- Xử lý lỗi: ERROR_NUMBER(), ERROR_MESSAGE(), ERROR_LINE()
END CATCH

Lời thầy giảng giải thích chi tiết:

  • Chống sập ứng dụng: Nếu không có TRY CATCH, khi xảy ra lỗi runtime (chia cho 0, trùng khóa, vi phạm foreign key), SQL Server sẽ dừng ngang câu lệnh và báo lỗi đỏ. Khi có TRY CATCH, quyền điều khiển chuyển sang khối CATCH một cách an toàn.
  • Vị trí bắt buộc: Khối BEGIN CATCH phải được đặt ngay sát phía sau END TRY, không được xen kẽ bất kỳ câu lệnh nào ở giữa.
  • Lấy dòng lỗi: Hàm ERROR_LINE() chỉ ra chính xác số dòng code gây lỗi, và ERROR_MESSAGE() lấy câu thông báo lỗi để lưu vào bảng log hoặc thông báo ra màn hình.
